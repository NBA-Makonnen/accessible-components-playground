# Component Implementation Notes

## Overview
This document compares our custom-built ARIA components against the primitives generated by `shadcn/ui` (powered by Radix UI). 

## Concrete Gaps Between Custom vs. Shadcn Implementations

### 1. DOM Hierarchy and Portals (Dialog)
*   **Custom:** Renders the Modal exactly where it is placed in the component tree. This can cause severe `z-index` bugs or clipping if a parent element has `overflow: hidden` or lower stacking contexts.
*   **Shadcn/Radix:** Utilizes React Portals (`DialogPortal`) to append the modal directly to the `document.body`. This guarantees the modal sits above all other DOM elements visually and avoids CSS stacking context traps.

### 2. Body Scroll Locking (Dialog)
*   **Custom:** Allows the user to scroll the background page while the modal is open. (We would have to manually add `overflow: hidden` to the body element via a `useEffect`).
*   **Shadcn/Radix:** Uses `react-remove-scroll` under the hood. When the dialog opens, it automatically prevents background scrolling and adds necessary padding to the `body` to prevent the UI from shifting when the scrollbar disappears.

### 3. Robust Focus Trapping
*   **Custom:** Uses a simple DOM query (`querySelectorAll`) to find focusable elements and hijacks the `Tab` key. This breaks if elements are dynamically added/removed inside the modal, or if an iframe sits inside the modal.
*   **Shadcn/Radix:** Uses `FocusScope`, which handles edge cases like shadow DOMs, dynamically changing children, preventing focus from escaping to browser extensions, and managing pointer-events effectively.

### 4. Layout Shifts and Animation States (Tabs & Dialog)
*   **Custom:** Instantly toggles elements using the `hidden` attribute or unmounting. This makes CSS transitions (fade-ins/outs) difficult without complex state timing.
*   **Shadcn/Radix:** Integrates components like `Presence` that delay the unmounting of a component until its exit animation (like a fade-out) is fully complete.
